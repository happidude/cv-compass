# Brief O9 — Chặn tràn context + log cỡ context + .env.example đầy đủ (cờ mặc định tắt)

Mục tiêu/acceptance: cho phép hạ cỡ context (`CVC_LLM_CTX_CHARS_PER_TOKEN` cao hơn) mà KHÔNG có nguy cơ Ollama âm thầm cắt bớt đầu vào.
(1) Cờ `CVC_LLM_CTX_GUARD=true|false` (mặc định `false` = hành vi develop giữ nguyên từng byte). Khi bật, mỗi lần gọi model (lần gọi toàn văn, lần gọi header, mọi khối blocks) coi là **tràn context** nếu: Ollama trả lỗi về độ dài đầu vào/context, HOẶC `prompt_tokens + output_tokens >= num_ctx - 32` (dùng `last_metrics` của E11), HOẶC `done_reason=length` khi KHÔNG đặt `max_output_tokens`. Tràn → bỏ kết quả lần đó (không dùng một phần), gọi lại **một lần** với bậc context kế tiếp (8192→12288 nếu fine tiers, →16384→24576→32768). Lần gọi toàn văn vẫn tràn ở bậc cao nhất → đi đường `WHOLE_TOO_LONG` hiện có (chuyển blocks). Header/khối blocks tràn sau retry → issue nội bộ `CONTEXT_OVERFLOW` (field tương ứng), không gửi giá trị field đó. Thời gian/metrics của lần gọi bị bỏ vẫn được log.
(2) Log `extraction_block` thêm `num_ctx=<số>` (và `ctx_retry=1` khi có gọi lại); `lifecycle-report`/`bench` cộng thêm số lần `ctx_retry` và đếm CV theo bậc `num_ctx`. Không log nội dung.
(3) Cập nhật `llm-worker/.env.example`: liệt kê MỌI key trong `config.ENV_KEYS` (trừ token), nhóm Cơ bản / Tối ưu (đang tắt) / Nâng cao / Backend, mỗi key 1–2 dòng chú thích tiếng Việt: tác dụng khi bật + giá trị thử. Key không có giá trị mặc định hợp lệ khi rỗng (vd `CVC_LLM_WORKER_NAME`) để ở dạng comment. Thêm test: `.env.example` parse được bằng `_read_env` và chứa đủ key (trừ token).
Không đổi: prompt, schema, công thức chọn bậc ban đầu, payload gửi backend, provenance (`promptVersion` không đổi vì prompt không đổi).
Spec: file này. Chủ dự án 20/11/2026 duyệt hướng "chọn context sát + chốt an toàn". Số đo 20/11 (10 CV thật, chỉ số tổng hợp): prompt+output tối đa 7.244 token, 7/10 CV bị ước lượng lên 16384; ở 16384 tốc độ viết 6–9 tok/s so với 10–15 ở 8192.
